# 三人首轮任务

## 成员 A：数据与预测

首个交付：确定可获得的负荷、Solar、Wind Onshore/Offshore 实际时序及同一地区、同一时间段的覆盖情况；提供来源链接、地区代码和连续 48 小时样本。若三类数据无法对齐，立即报告，不要自行拼接不同地区的数据。

后续交付：`clean_hourly.csv`、清洗日志、时间切分配置、持续性预测、1—24 小时 q10/q50/q90 净负荷预测及预测评估。代码放在 `src/forecast/`。

## 成员 B：设备与调度

首个交付：`config/device_parameters.example.yaml` 中每项参数的拟定值、单位和来源，列出 SOC、氢量、功率平衡及设备互斥约束。未确认值注明“假设”，不能伪称实测。

后续交付：状态转移测试、规则基线、24 小时滚动 MILP、动态备用、四策略执行结果、无解/超时回退日志。代码放在 `src/dispatch/`。

## 成员 C：接口与评估

首个交付：本仓库、数据接口、样例和校验工具；请 A/B 用样例验证字段可被各自程序读写。

后续交付：`run_all.py`、统一指标与检查、四策略对照图、消融实验、报告和可复现提交包。代码放在 `src/evaluation/`。

任何成员交付时都应附上文件路径、运行命令、使用的配置、样本覆盖时段和已知问题。先让最小流程跑通，再替换成完整模型。
